  Optional columns (the pipeline will pick them up automatically if present)

  These match config.OPTIONAL_NUMERIC_FEATURES. Each gets a _present indicator so the surrogate can tell "not measured" from "measured = 0":

  ├───────────────────────┼─────────────────────────────┤

  If you also have reaction conditions (T, P, GHSV, H2/HC ratio), the slots are commented out in config.py:OPTIONAL_NUMERIC_FEATURES (line 63-66) — uncomment whichever you have and use the exact
  column names: reaction_temp_C, reaction_pressure_atm, GHSV_h, H2_HC_ratio.

  Things to know before uploading

  1. Names in the active_metal / promoter / support columns must match the lookup keys exactly (case-sensitive). If you have a metal or oxide we don't have, add a row to the relevant lookup CSV
  with its physical properties. The pipeline will fail silently (NaN features) for unknown names — easy to miss.
  2. If you have non-zero promoter loading but the promoter cell is empty, the row will look inconsistent. Either fill the promoter or zero the loading.
  3. Targets: use whatever your measured outputs are (e.g. propylene_yield_pct, propylene_selectivity_pct, TOF_h-1). For TOF, log-transform if values span > 2 orders of magnitude (the surrogate
  generalizes better on log scale).
  4. Row count: anything from 50 rows up works; the parity verdict will tell you honestly whether the surrogate generalizes (the synthetic 72-row run was clearly in the "speculative" regime).
  5. Two-target vs one-target: pick in the webui tab 1; the pipeline switches between BO (single) and MOBO (dual) automatically.
  6. First-run sanity check: the webui's tab 2 (Data Exploration → Overview / Missing / Distributions / Outliers / Correlations) is the right place to gut-check the dataset before letting BO
  touch it.
